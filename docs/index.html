Scanner API Gateway v1.2.0 · contract_version 1

A command-line scanning API. Launch one executable, pass arguments, read one JSON object from stdout. No manufacturer SDK, no GUI, no DLL to link, no COM interop in your application.

Source and releases: github.com/RatioJuris/ScannerAPIGateway. Release notes: CHANGELOG.md.

Why use it

BackendHow it connectsManufacturer software needed
escleSCL/AirScan over HTTP and mDNS (network scanners and MFPs)No — open standard built into the device
wiaWindows Image Acquisition 2.0 (built into Windows)No — uses the OS class driver where available
twain32-bit or 64-bit TWAIN Data Source ManagerOnly the scanner's TWAIN data source, not a bundled utility app

Linux and macOS builds expose escl only. WIA and TWAIN are Windows APIs. Use a Windows build for locally attached scanners that do not support eSCL.

Quick start

# Discover scanners
ScannerAPIGateway list

# Scan with defaults into a directory (files are named automatically)
ScannerAPIGateway scan --out C:\scans\

# Scan a network scanner, grayscale, 300 dpi, duplex ADF, skip blank pages
ScannerAPIGateway scan --device "escl:http://192.168.1.50:80/eSCL" \
  --source duplex --mode gray --dpi 300 --blank-skip 0.05 \
  --format jpeg --out C:\scans\batch\ --verbose

# Version / usage
ScannerAPIGateway version
ScannerAPIGateway help

Commands

CommandDescription
listDiscovers devices. Accepts --backends. Always exits 0; per-backend health is in the JSON.
scanRuns a scan job. --out is required.
versionReturns version, vendor, available backends and architecture.
helpPrints plain-text usage to stdout (not JSON).

--device <id|auto>autoUse an id from list for deterministic targeting.

Output contract

stdout is always exactly one JSON object (except help). stderr is used only for --verbose progress. All 1.x responses carry "contract_version":1.

Successful version

{"ok":true,"contract_version":1,"command":"version",
 "name":"Scanner API Gateway by RatioJuris","vendor":"RatioJuris",
 "version":"1.2.0","copyright":"© 2026 RatioJuris",
 "backends":["wia","twain","escl"],"arch":"x64"}

On Linux/macOS, backends is ["escl"] and arch is x64 or arm64. Field names never change.

Successful list

{"ok":true,"contract_version":1,"command":"list",
 "devices":[{"id":"escl:http://192.168.1.50:80/eSCL","name":"Office MFP",
             "description":"AirScan","manufacturer":"Canon","kind":"scanner","backend":"escl"}],
 "backends":[{"name":"escl","available":true}]}

backends[].available is false when a subsystem is missing; message then explains why. list still exits 0.

Successful scan

{"ok":true,"contract_version":1,"command":"scan","backend":"escl",
 "device":"escl:http://192.168.1.50:80/eSCL",
 "settings":{"mode":"gray","dpi":300,"source":"duplex","format":"jpeg"},
 "page_count":2,"skipped_blank_pages":1,
 "pages":[{"index":1,"path":"C:\\scans\\SCAN_20261120_101500_p0001.jpg",
           "content_type":"image/jpeg","bytes":184322}],
 "warnings":[],"elapsed_ms":4120}

Paths are absolute. Page order is the order pages were acquired. skipped_blank_pages counts pages discarded before naming, so indices stay contiguous.

Error

{"ok":false,"contract_version":1,
 "error":{"code":"paper_empty","message":"No paper in the document feeder."}}

Exit codes

CodeMeaningTypical error.code values
0Success—
1General failureinternal_error, scan_failed, output_error
2Bad argumentsinvalid_argument, unknown_option, missing_value, usage
3No scannerno_scanner, device_not_found
4Timeouttimeout
5Hardware statepaper_empty, paper_jam, cover_open, device_busy, multi_feed
6Backend unavailablewia_unavailable, twain_unavailable, escl_unavailable, device_communication

Branch on the numeric exit code and error.code, never on message text.

Integrating from your app

import json, subprocess

EXE = r"C:\path\to\ScannerAPIGateway.exe"   # or ./ScannerAPIGateway on Linux/macOS

def call(*args):
    p = subprocess.run([EXE, *args], capture_output=True, text=True, encoding="utf-8")
    return p.returncode, json.loads(p.stdout)

code, found = call("list")
if code != 0:
    raise RuntimeError(found["error"]["message"])

device = next((d["id"] for d in found["devices"] if d["backend"] == "escl"), "auto")
code, result = call("scan", "--device", device, "--out", r"C:\scans\", "--dpi", "300")
if code != 0:
    raise RuntimeError(result["error"]["message"])

for page in result["pages"]:
    process(page["path"])

The same pattern works from C#, Node.js, PowerShell, Java or any language that can spawn a process and parse JSON. Do not link against the executable; it is a standalone CLI API. Always set --verbose only when you want stderr output.

Builds and artifacts

GitHub Actions builds every release. Tagged v1.2.0 publishes:

  • Windows x86 (32-bit) executable
  • Windows x64 (64-bit) executable
  • Windows portable ZIP containing the executable
  • Linux builds for major architectures (x64, arm64)
  • macOS builds for x64 and arm64
  • SHA-256 checksum file for every artifact

Windows builds include all three backends. Linux/macOS builds are eSCL-only.
